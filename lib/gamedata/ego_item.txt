# Archivo: ego_item.txt


# Este archivo se utiliza para inicializar la información de los "objetos de ego" para Angband.

# No modifiques este archivo a menos que sepas exactamente lo que estás haciendo,
# a menos que quieras arriesgarte a posibles caídas del sistema y archivos guardados dañados.

# Ten en cuenta que varios tipos de "objetos de ego" pueden compartir el mismo "nombre textual",
# como con "Armadura de Resistencia" y "Escudo de Resistencia".

# === Entendiendo ego_item.txt ===

# name: tipo de ego
# info: coste : valoración
# alloc: frecuencia : mín " to " máx
# combat: para-golpear : para-dañar : para-CA
# min-combat: mín para-golpear : mín para-dañar : mín para-CA
# type: tval
# item: tval : sval
# flag: bandera | bandera | etc.
# flags-off: bandera | bandera | etc
# values: etiqueta[valor] | etiqueta[valor] | etc.
# min-values: etiqueta[valor] | etiqueta[valor] | etc.
# act: nombre
# time: valor aleatorio de tiempo de espera
# brand: código
# slay: código
# curse: nombre : poder
# desc: descripción

# Algunos campos aceptan números aleatorios de la forma "10+2d3M4" donde
# 10 es la base no variable, 2d3 es una tirada de dados estándar, y
# M4 usa la función m_bonus para generar un número entre 0 y
# 4 según una distribución normal. Los tres componentes son
# opcionales, y el número de dados es opcional y se asume que es 1
# cuando no se especifica. 10+2d3M4 tiene el rango 12-20. 10+M4 tiene el
# rango 10-14. 10+2d3 tiene el rango 12-16. 10+d3 tiene el rango 11-13.
# 2d3, d3, M4, 2d3M4, y d3M4 también son aceptables. Las expresiones
# aleatorias que comienzan con "-" se manejan actualmente de manera diferente en la
# línea "values" que en otros lugares. En la línea "values", el "-"
# inicial establece el signo del valor base (ej. 10 en el ejemplo). En otras líneas,
# un "-" inicial en la expresión aleatoria significa multiplicar el resultado aleatorio
# de lo que sigue por menos uno. Como resultado, algo como "-d4" no
# funcionará como se desea cuando se usa para una línea "values". Usa "-5+1d4" en su lugar.

# 'name' indica el comienzo de una entrada.

# 'info' es para la información del objeto. El coste es el valor del objeto y la valoración
# afecta las sensaciones de nivel.

# 'alloc' es para los detalles de asignación. La frecuencia determina qué tan común
# es el objeto, la profundidad mínima es la más temprana en la que se encuentra normalmente, la profundidad
# máxima es la más profunda en la que se encuentra alguna vez. La "profundidad de asignación" no
# necesita coincidir con la profundidad especificada en la línea "info:".

# 'combat' es para las bonificaciones de combate - para-golpear, para-dañar, para-CA.
# Los objetos de ego malditos negarán el valor dado. Estas son
# bonificaciones adicionales sobre los valores normales, y todos estos
# campos aceptan valores aleatorios.

# 'min-combat' es para los valores mínimos - mínimo permitido para-golpear, para-dañar, para-CA.
# El valor 255 es especial, significa "no hay mínimo". Esto
# permite que cero sea un mínimo válido (ej. para objetos de bendición mixta).

# 'type' es para posibles tvals (bases de objeto). Una línea 'type' indica
# que cualquier tipo de objeto de ese tipo puede usarse para generar este objeto de ego.

# 'item' es para posibles pares tval-sval, que corresponden a tipos de objetos.
# Se usan una o más líneas 'item' cuando no queremos que todos los tipos de objeto de
# este tval sean posibles para este objeto de ego.

# 'flags' es para las banderas, que pueden ser banderas de objeto (como se encuentran en
# src/list-object-flags.h) o banderas de tipo (src/list-kind-flags.h). Se pueden usar tantas
# líneas flags: como sean necesarias para especificar todas las banderas, y
# las banderas se separan con el símbolo '|'.

# 'flags-off' es para las banderas a eliminar del objeto base. Por ejemplo, en
# object.txt, a las linternas se les da TAKES_FUEL. No queremos que las linternas
# (Everburning) consuman combustible, así que añadimos una línea 'flags-off:TAKES_FUEL' para restar
# esa bandera.

# 'values' es para las propiedades que toman un valor. Las propiedades válidas son los
# modificadores de objeto (como se encuentran en list-stats.h y list-object-modifiers.h)
# o resistencias ('RES_' antepuesto al nombre del elemento de list-elements.h).
# El valor aparece entre corchetes después del nombre de la propiedad. Para los modificadores de objeto,
# el valor puede ser cualquier expresión aleatoria. Para las resistencias, debe ser un
# valor entero simple, siendo los útiles 1 (resistencia), 3 (inmune), y -1
# (vulnerable). Como las banderas, los valores se separan por '|' y se pueden usar tantas
# líneas values: como sean necesarias.

# 'min-values' es para los valores mínimos de los valores registrados en una línea 'values'.
# Estos funcionan como los valores mínimos de combate, pero para modificadores definidos por valor.
# Si bien las resistencias se pueden especificar en una línea 'values', no pueden aparecer
# en una línea 'min-values'. Además, a diferencia de la línea 'values', todos los valores deben
# ser números enteros simples: no se permiten expresiones aleatorias completas.

# 'act' es cualquier activación que el ego pueda tener - la mayoría no tiene ninguna. La
# activación se especifica por su nombre, como se encuentra en activation.txt.

# 'time' da un valor aleatorio para ser usado como el tiempo de recarga para la
# activación.

# 'brand' añade una marca al ego. Debe omitirse para egos sin
# marcas y puede aparecer más de una vez para egos con múltiples marcas. Especifica
# la marca a añadir por su código en brand.txt.

# 'slay' añade un azote al ego. Debe omitirse para egos sin azotes
# y puede aparecer más de una vez para egos con múltiples azotes. Especifica el azote
# a añadir por su código en slay.txt.

# 'curse' añade una maldición al ego. Debe omitirse para egos sin maldiciones
# y puede aparecer más de una vez para egos con múltiples maldiciones. Una maldición tiene un
# nombre (como se da en curse.txt) y un poder. El poder es un entero positivo
# e indica lo difícil que es eliminar la maldición. Un poder mayor es más
# difícil de eliminar.

# 'desc' es para la descripción. Se pueden usar tantas líneas desc: como sean necesarias
# para describir el objeto. Ten en cuenta que las líneas necesitarán espacios al final
# o al principio de la siguiente línea para evitar que las palabras se junten.
