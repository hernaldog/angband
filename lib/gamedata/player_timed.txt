# Archivo: player_timed.txt

# Utilizado en conjunto con list-player-timed.h
# Propiedades temporales del jugador

# Las descripciones, mensajes y tipos de mensaje se pueden editar sin malos efectos.
# Cambiar fail puede tener resultados impredecibles.
# Cambiar el nombre o añadir entradas completamente nuevas alterará gravemente el juego.
# Solo debe hacerse cuando list-player-timed.h (y otro código) también se esté
# cambiando, y el juego sea recompilado.
# Cambiar una línea de resist deberá coincidir con uno de los elementos codificados
# de list-elements.h; actualmente, esas líneas de resist se utilizan en los
# cálculos de resistencia del jugador, para filtrar mensajes innecesarios cuando los
# efectos temporales caducan y para afectar la selección de activaciones de randarts.
# Cambiar una línea de marca o azote deberá coincidir con una entrada en brand.txt o
# slay.txt, respectivamente; además del efecto en combate, esas líneas también
# afectan la selección de activaciones de randarts.
# Cambiar una línea de sinónimo de bandera deberá coincidir con una entrada, de tipo flag, en
# object_property.txt; esas líneas se utilizan actualmente en los cálculos del jugador,
# para filtrar mensajes innecesarios cuando los efectos temporales caducan y para afectar
# la selección de activaciones de randarts.

# Campos:
# name - el nombre del efecto; el nombre debe coincidir con el primer argumento de una de las
#        macros TMD() en list-player-timed.h
# desc - la descripción del efecto
# grade - especifica un grado para este efecto; la mayoría de los efectos solo tienen dos grados:
#         off (implícito para todos los efectos, máximo de 0, sin mensajes de transición)
#         y on (el único grado especificado para el efecto en este archivo)
#         parámetro uno: color utilizado en la línea de estado para este efecto cuando está en este
#             grado; puede ser un código de color de una letra o el nombre completo del color
#             (no sensible a mayúsculas)
#         parámetro dos: es el máximo para este grado; para funcionar correctamente debe ser
#             mayor que cero, menor que 32768, y mayor que el máximo
#             de cualquier grado anterior especificado para este efecto
#         parámetro tres: es el nombre del grado y se mostrará en la línea de
#             estado; usa un nombre de un carácter para el grado para suprimir
#             la visualización del efecto temporal en la línea de estado cuando se está en ese grado
#         parámetro cuatro: es el mensaje a mostrar cuando el efecto entra en este
#             grado desde un grado inferior; no se mostrará ningún mensaje si el
#             mensaje tiene un carácter de longitud
#         parámetro cinco (opcional): es el mensaje a mostrar cuando el efecto
#             entra en este grado desde un grado superior; no se mostrará ningún
#             mensaje si se omite este parámetro
# on-end - el mensaje al finalizar el efecto
# on-increase - el mensaje al aumentar el efecto
# on-decrease - el mensaje al disminuir el efecto
# msgt - el tipo de mensaje a usar para los mensajes de cambio de grado, on-increase, y
#        on-decrease para este efecto; el tipo debe coincidir (sin distinción de
#        mayúsculas/minúsculas) con el primer argumento de una de las macros MSG() en
#        list-message.h o ser un entero sin signo menor que MSG_MAX que sea
#        el índice del tipo de mensaje a usar dentro de list-message.h; los mensajes
#        on-end siempre usan el tipo de mensaje RECOVER; para la interfaz de usuario textui,
#        el tipo de mensaje afecta el color del mensaje (configurado globalmente por
#        lib/customize/message.prf; también configurable por preferencias en los archivos del
#        usuario) y el sonido reproducido cuando se muestra el mensaje (configurado
#        globalmente por lib/customize/sound.prf; también configurable por preferencias en los
#        archivos del usuario)
# fail - determina qué hace que el efecto falle; puede especificarse más de una
#        vez: el efecto fallará si se cumple alguna de las condiciones
#        parámetro uno:
#          1 - bandera de objeto
#          2 - resistencia
#          3 - vulnerabilidad
#          4 - bandera de jugador
#          5 - presencia de efecto temporal
#        parámetro dos:
#          la bandera real que causa el fallo; para una bandera de objeto, la
#          bandera debe coincidir con el primer argumento de una de las macros OF() en
#          list-object-flags.h; para una bandera de jugador, la bandera debe coincidir con el
#          primer argumento de una de las macros PF() en list-player-flags.h; para
#          una resistencia o vulnerabilidad, la bandera debe coincidir con el argumento de una
#          de las macros ELEM() en list-elements.h; para un efecto temporal, la
#          bandera debe coincidir con el argumento de una de las macros TMD() en
#          list-player-timed.h
# on-begin-effect - (opcional) especifica un efecto que se invocará cuando comience el
#                   efecto temporal; se puede usar más de una vez: los
#                   efectos adicionales se ejecutarán en el orden en que
#                   aparecen
#                   parámetro uno: nombre del efecto (argumento de una de las
#                       macros EFFECT() en list-effects.h)
#                   parámetro dos: nombre del subtipo del efecto; se puede
#                       omitir
#                   parámetro tres: radio del efecto; se puede omitir y
#                       debe omitirse si se omite el subtipo
#                   parámetro cuatro: el parámetro "other" para el efecto; se puede
#                       omitir y debe omitirse si se omite el subtipo o el radio
# on-end-effect - (opcional) especifica un efecto que se invocará cuando el efecto
#                 temporal caduque; se puede usar más de una vez: los efectos
#                 adicionales se ejecutarán en el orden en que aparecen
#                 parámetro uno: nombre del efecto (argumento de una de las
#                     macros EFFECT() en list-effects.h)
#                 parámetro dos: nombre del subtipo del efecto; se puede omitir
#                 parámetro tres: radio del efecto; se puede omitir y debe
#                     omitirse si se omite el subtipo
#                 parámetro cuatro: el parámetro "other" para el efecto; se puede
#                     omitir y debe omitirse si se omite el subtipo o el radio
# effect-yx - (opcional) especifica los parámetros y y x del efecto establecido más
#             recientemente (ej. de una directiva on-begin-effect o on-end-effect
#             anterior)
#             parámetro uno: es el valor del parámetro y para el efecto
#             parámetro dos: es el valor del parámetro x para el efecto
# effect-dice - (opcional) especifica la cadena de dados para el efecto establecido más
#               recientemente (ej. de una directiva on-begin-effect o on-end-effect
#               anterior)
# effect-expr - (opcional) define una expresión para la cadena de dados del
#               efecto establecido más recientemente (ej. de una directiva on-begin-effect
#               o on-end-effect anterior); requiere que la cadena de dados se haya
#               establecido para el efecto con una directiva effect-dice
#               parámetro uno: es el nombre de la variable a sustituir con el
#                   valor de la expresión; los nombres de las variables deben ser
#                   todo en mayúsculas y una referencia a una variable en una cadena
#                   de dados comienza con $; si la cadena de dados no contiene
#                   una referencia a la variable dada, el análisis de los archivos
#                   de datos del juego se detendrá con un error
#               parámetro dos: establece el nombre del valor base a modificar con las
#                   operaciones en el tercer parámetro; el nombre puede ser uno de
#                   los que se enumeran a continuación; si no coincide con ninguno de la lista,
#                   el valor base será cero
#                     PLAYER_LEVEL - el nivel del jugador
#                     DUNGEON_LEVEL - el nivel de la mazmorra
#                     MAX_SIGHT - el rango de visión máximo, en casillas
#                     WEAPON_DAMAGE - una tirada aleatoria para el daño base (solo
#                         se incluyen los dados y modificadores de daño del arma;
#                         no se utilizan modificadores de daño del jugador o equipo
#                         que no sea el arma) del arma equipada del jugador;
#                         si el jugador no tiene un arma equipada, el valor de esto es cero
#                     PLAYER_HP - el número actual de puntos de golpe del jugador
#                     MONSTER_PERCENT_HP_GONE - ((puntos de golpe máximos para el
#                         monstruo objetivo del jugador - puntos de golpe actuales para el
#                         monstruo objetivo del jugador) * 100) / puntos de golpe máximos
#                         para el monstruo objetivo del jugador o 0 si el jugador
#                         no tiene actualmente un monstruo objetivo
#               parámetro tres: establece las operaciones a realizar en el valor base para
#                   obtener el valor sustituido en la expresión de dados; por
#                   ejemplo, "* 2 / 3" multiplicaría el valor base por 2 y luego
#                   dividiría ese resultado por tres, descartando cualquier resto;
#                   los operadores permitidos son '+' (suma),
#                   '-' (resta), '*' (multiplicación), '/' (división
#                   entera; descarta el resto), y 'n' o 'N' (niega
#                   el resultado anterior al operador);
#                   las constantes enteras en las operaciones deben estar entre -32768 y 32767;
#                   los operadores y las constantes enteras en las operaciones deben estar
#                   separados por espacios simples
# effect-msg - (opcional) añade al mensaje asociado con el efecto establecido más
#              recientemente (ej. de una directiva on-begin-effect o
#              on-end-effect anterior); cómo se usa ese mensaje depende
#              del efecto - normalmente puede imprimirse durante el efecto o
#              usarse como mensaje de muerte
# resist - (opcional) cuando esta propiedad temporal está activa, el receptor gana
#          una resistencia temporal al elemento nombrado
# brand - (opcional) cuando esta propiedad temporal está activa, el receptor gana
#         la marca dada (por su código en brand.txt) en las armas equipadas; cuando
#         no hay línea de marca, la propiedad temporal no induce una marca
# slay - (opcional) cuando esta propiedad temporal está activa, el receptor gana
#        el azote dado (por su código en slay.txt) en las armas equipadas; cuando
#        no hay línea de azote, la propiedad temporal no induce un azote
# flag-synonym - (opcional) indica que esta propiedad temporal es (en gran parte)
#                sinónimo de la propiedad de objeto de tipo flag en
#                object_property.txt con el código dado por el primer parámetro;
#                si el segundo parámetro no es cero, esta propiedad temporal es un
#                sinónimo exacto, excepto por la duración; si el segundo parámetro es
#                cero, la propiedad temporal tiene otros efectos que no están
#                implícitos en la propiedad de objeto nombrada
# lower-bound - (opcional) anula el límite inferior por defecto de cero para el
#               efecto temporal; el límite inferior debe ser no negativo, menor
#               que 32768, y menor o igual que el máximo de cualquiera de
#               los grados del efecto temporal; si el límite inferior es mayor que
#               cero, el efecto temporal está siempre activo (por lo que un mensaje establecido por
#               on-end o un efecto por on-begin-effect o on-end-effect no
#               se utilizará)
# flags - (opcional) especifica una o más banderas para el efecto temporal; puede
#         aparecer más de una vez y todas las banderas especificadas se acumulan;
#         se puede especificar más de una bandera cada vez que se usa; los nombres
#         de las banderas deben estar separados por espacios o '|'; los nombres de las banderas
#         que se entienden son:
#         NONSTACKING - cualquier intento de aumentar el efecto temporal mientras ya
#             está activo no aumentará la duración; esta es una restricción más
#             fuerte que tener el efecto temporal fallar debido al propio
#             efecto temporal, principalmente porque NONSTACKING también afecta
#             casos, como los efectos TIMED_INC_NO_RES, donde la verificación de fallo se
#             omite; NONSTACKING también se maneja de manera diferente a fallar
#             para el propio efecto temporal en términos de comprobaciones de saber (si un efecto
#             temporal es NONSTACKING, el saber de un monstruo no mostrará que el
#             ataque del monstruo que inflige ese estado es resistido únicamente
#             porque el personaje ya está sujeto al efecto temporal)
