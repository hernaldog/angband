# Archivo: object.txt
#
# Este archivo se utiliza para inicializar la información de los "tipos de objetos" para Angband.
# Modificar este archivo cuando no sabes lo que estás haciendo puede ser perjudicial
# para ti o para la salud de tu personaje. También podría considerarse hacer trampa
# bajo algunas circunstancias. :)

# === Comprendiendo object.txt ===

# name: & nombre del objeto~
# graphics: símbolo : color
# type: tval
# level: nivel
# weight : peso
# cost : coste
# attack : daño base : bonificación para-golpear : bonificación para-dañar
# armor: clase de armadura base : bonificación a CA
# alloc: frecuencia : nivel_mín a nivel_máx
# charges: cargas
# pile: probabilidad de generarse en un montón : dados para el número de objetos
# power: poder del efecto para las evaluaciones de poder del objeto
# msg: mensaje al usar el objeto
# vis-msg: mensaje al usar el objeto, solo cuando el jugador no está ciego
# effect: efecto al ser usado : subtipo (opcional) : radio (opcional) : parámetro (opcional)
# effect-yx: valor y para el efecto : valor x para el efecto
# dice:cadena de dados
# expr:código de sustitución:valor base:expresión
# flags: bandera | bandera | etc.
# values: etiqueta[valor] | etiqueta[valor] | etc.
# brand: código
# slay: código
# curse: nombre : poder
# pval: pval
# desc: descripción

# Algunos campos aceptan números aleatorios de la forma "10+2d3M4" donde
# 10 es la base no variable, 2d3 es una tirada de dados estándar, y
# M4 usa la función m_bonus para generar un número entre 0 y
# 4 según una distribución normal. Los tres componentes son
# opcionales, y el número de dados es opcional y se asume que es 1
# cuando no se especifica. 10+2d3M4 tiene el rango 12-20. 10+M4 tiene el
# rango 10-14. 10+2d3 tiene el rango 12-16. 10+d3 tiene el rango 11-13.
# 2d3, d3, M4, 2d3M4, y d3M4 también son aceptables. Las expresiones
# aleatorias que comienzan con "-" se manejan actualmente de manera diferente en la
# línea "values" que en otros lugares. En la línea "values", el "-"
# inicial establece el signo del valor base (ej. 10 en el ejemplo). En otras líneas,
# un "-" inicial en la expresión aleatoria significa multiplicar el resultado aleatorio
# de lo que sigue por menos uno. Como resultado, algo como "-d4" no
# funcionará como se desea cuando se usa para una línea "values". Usa "-5+1d4" en su lugar.

# 'name' indica el comienzo de una entrada. Los símbolos '&' y '~' se usan para
# incluir artículos y pluralización según sea necesario para asegurar la
# corrección gramatical en las descripciones de los objetos.
#
# Para plurales no ingleses e irregulares, se puede usar el símbolo '|'
# en su lugar, como en "|singular|plural|". La parte entre el primer y
# segundo símbolo | se usa para el singular, y la parte entre el segundo
# y el tercero | para el plural. El número de símbolos | en el nombre debe
# ser siempre un múltiplo de 3.

# 'graphics' es para el símbolo y el color. Hay 27 colores, como
# sigue:

# D - Gris Oscuro    w - Blanco          s - Gris          o - Naranja
# r - Rojo          g - Verde           b - Azul          u - Ocre
# W - Gris Claro    P - Púrpura Claro   y - Amarillo      R - Rojo Claro
# G - Verde Claro   B - Azul Claro      U - Ocre Claro    p - Púrpura
# v - Violeta       t - Verde Azulado   m - Marrón        Y - Amarillo Claro
# i - Magenta-Rosa  T - Verde Azulado Claro V - Violeta Claro I - Rosa Claro
# M - Mostaza       z - Pizarra Azul    Z - Azul Claro Profundo

# Otro color, "d", se usa para objetos "con sabor".

# 'type' es para el tipo base del objeto, de object_base.txt.

# 'level' define lo "avanzado" que es el objeto, al determinar lo fácil que
# es usar con éxito una varita, báculo o vara. Para un objeto con una activación,
# afecta la probabilidad de activar el objeto con éxito. De manera similar,
# afecta la probabilidad de que una varita o báculo pueda ser recargado sin
# salir mal. Para un cofre, el nivel afecta los tipos de trampas que el cofre
# puede tener.

# 'weight' está en décimas de libra.

# 'cost' es el valor base del objeto.

# 'attack' es para la información de ataque de combate, el daño base del objeto y
# los pluses para-golpear y para-dañar. El daño base debe ser una tirada de dados estándar
# (ej. 2d5), y los dos últimos números pueden ser cualquier valor aleatorio como arriba.

# 'armor' es para la información de armadura, la clase de armadura base del objeto y la bonificación a CA.
# Esta última acepta valores aleatorios.

# 'alloc' es para la asignación: frecuencia y rango de niveles en los que se encuentra. Se usa para
# asegurar que ciertos objetos vitales como la comida y los pergaminos de retorno
# se encuentran en toda la mazmorra. La "profundidad de asignación" no necesita
# coincidir con el nivel del objeto especificado en la línea "level:", pero es probablemente similar.
# - frecuencia: Peso de probabilidad relativo (mayor = más común)
# - min_level: Nivel de mazmorra más temprano donde este objeto puede aparecer
# - max_level: Nivel de mazmorra más tardío donde este objeto puede aparecer

# 'charges' es para las cargas (solo varitas y báculos). Este campo acepta
# valores aleatorios.

# 'pile' es para el comportamiento de montón: la probabilidad de que el objeto se encuentre en un
# montón, y cuántos (valor aleatorio) objetos en dicho montón. Los objetos
# sin una línea pile aparecen individualmente.

# 'flags' es para las banderas, que pueden ser banderas de objeto (como se encuentran en
# src/list-object-flags.h) o banderas de tipo (src/list-kind-flags.h). Se pueden usar tantas
# líneas flags: como sean necesarias para especificar todas las banderas, y
# las banderas se separan con el símbolo '|'.

# 'values' es para las propiedades que toman un valor. Las propiedades válidas son los
# modificadores de objeto (como se encuentran en list-stats.h y list-object-modifiers.h)
# o resistencias ('RES_' antepuesto al nombre del elemento de list-elements.h).
# El valor aparece entre corchetes después del nombre de la propiedad. Para los modificadores de objeto,
# el valor puede ser cualquier expresión aleatoria. Para las resistencias, debe ser un
# valor entero simple, siendo los útiles 1 (resistencia), 3 (inmune) y -1
# (vulnerable). Como las banderas, los valores se separan por '|' y se pueden usar tantas
# líneas values: como sean necesarias.

# 'brand' añade una marca al objeto. Debe omitirse para objetos
# sin marcas y puede aparecer más de una vez para objetos con múltiples marcas.
# Especifica la marca a añadir por su código en brand.txt.

# 'slay' añade un azote al objeto. Debe omitirse para objetos sin
# azotes y puede aparecer más de una vez para objetos con múltiples azotes. Especifica
# el azote a añadir por su código en slay.txt.

# 'curse' añade una maldición al objeto. Debe omitirse para objetos sin
# maldiciones y puede aparecer más de una vez para objetos con múltiples maldiciones. Una
# maldición tiene un nombre (como se da en curse.txt) y un poder. El poder es un
# es un entero positivo e indica lo difícil que es eliminar la maldición. Un
# poder mayor es más difícil de eliminar.

# 'power' se usa para calcular el poder del objeto para la fijación de precios y la
# generación de artefactos aleatorios. Refleja el poder del efecto del
# objeto; otras propiedades se tienen en cuenta por separado en el cálculo de
# poder.

# 'msg' es cualquier mensaje impreso al usar el objeto.

# 'effect' es para el efecto cuando un objeto se come, activa o lo que sea.
# Los campos son el nombre del efecto (como se encuentra en src/list-effects.h), el
# subtipo que es ya sea un índice o un nombre (mira effect_subtype()
# en src/effects.c para más información sobre los subtipos disponibles), el
# radio y el otro parámetro. El nombre del efecto es obligatorio. Los demás
# son opcionales, y los últimos que no se usen pueden omitirse.

# 'effect-yx' son los valores y y x para un efecto si es necesario.

# 'dice' proporciona un valor aleatorio para ser usado por un efecto (para daño,
# curación, etc.). Además de los campos de valor aleatorio normales descritos anteriormente,
# puede contener expresiones como $B, que hacen referencia a una línea 'expr' posterior.

# 'expr' proporciona una expresión para usar en los dados de efecto. Consiste en una
# letra de código (ej. B) para la expresión, una función base a usar (por ejemplo
# PLAYER_LEVEL), y una secuencia de operaciones a realizar sobre esa base.

# 'time' da un valor aleatorio para ser usado como el tiempo de recarga de una vara o
# objeto activable.

# 'pval' es para pval - un valor auxiliar que puede significar valor de comida,
# multiplicador de lanzador o turnos de luz. Un pval puede tomar un valor aleatorio.

# 'desc' es para la descripción. Se pueden usar tantas líneas desc: como sean necesarias
# para describir el objeto. Ten en cuenta que las líneas necesitarán espacios al final
# o al principio de la siguiente línea para evitar que las palabras se junten.
